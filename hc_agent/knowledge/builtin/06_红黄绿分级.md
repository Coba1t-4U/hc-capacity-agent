# 红黄绿分级与数据风险

承载力结论带一个等级，用于对外快速表达"还能不能接"。

## 分级规则（HC-RULES@1.0 批准）

- `red_at_or_below_kw: 0` —— 容量 **≤ 0 kW 时判为红色**
- `yellow_margin_ratio: 0.15` —— 容量在阈值附近 15% 余量内判为黄色
- `grey_on_data_risk: true` —— 存在数据风险时判为**灰色**

## 四个等级的含义

| 等级 | 含义 | 对外表述 |
|---|---|---|
| green 绿色 | 有充裕的开放空间 | 可接，按管理口径答复 |
| yellow 黄色 | 空间紧张，接近限值 | 谨慎接入，需复核 |
| red 红色 | 无开放容量（0 或负） | 不可接，须先治理 |
| grey 灰色 | 内部态：存在数据风险或能力未覆盖 | **不对外发布** |

## 灰色为什么单独存在

灰色是**内部态**，不是"第五种颜色"的结论。它表示：

- 有约束算不出来（unknown），或
- 输入数据存在风险

此时不能给红黄绿任何一档，因为结论可能不成立。
灰色结果**不应该对外发布**，应先补齐数据或能力再重算。

所以看到一个算例"容量 0 kW 但等级是灰色"时，
正确理解是：它的容量确实算出来是 0，但因为有未覆盖项，
这个 0 还不足以支撑对外发布。

## 读等级时的常见误判

1. **把灰色当绿色。** 灰色不是"没问题"，是"还不能下结论"。
2. **只看容量不看等级。** 有容量但等级灰色，仍然不能发布。
3. **把 red 理解成"设备坏了"。** red 表示没有开放容量，
   原因可能是基线就越限，也可能是某个约束在很小容量下就触发。
   具体原因要看 `binding_constraint` 与 `binding_detail`。
