# 独立复算与发布门禁

承载力结论要对外发布，必须过三道门禁。任一未满足即**不得发布**，
结果只能作为候选。

## 三道门禁

| 门禁 | 含义 |
|---|---|
| 独立复算 `independent_verification` | 用**另一条引擎通道**重跑，逐字段比对 |
| 专业复核 `professional_review` | 由专业人员在系统内确认 |
| 审批 `approval` | 按流程完成审批 |

三者都满足，`release_gate.passed` 才是 true。

常见状态是：独立复算已通过，但专业复核与审批还没做，
于是 `passed: false`、`failed_gates: ["professional_review", "approval"]`。
这**不是程序出错**，而是流程还没走完。

## 独立复算做什么

目的不是"再算一遍确认没算错"，而是**发现单一引擎通道的系统性错误**：

- 换通道重跑同一算例
- 逐字段比对两次结果（电压、负载率、容量）
- 输出差异项数与各项差值
- 判断两次的**输入**是否一致

比对容差由 `verification.metric_tolerances_ref` 指定，本规则包为：

- 电压：绝对 1e-6 pu
- 负载率：绝对 1e-4 %
- 容量：绝对 1e-3 kW

超出容差即记为差异项（mismatch）。差异项为 0 才叫通过。

## 复算产物在哪

- `verification/verification.json`：结论、是否通过、输入是否一致
- `review/release_gate.json`：三道门禁的状态、未满足项
- `review/publication.json`：发布记录

## 回答"能不能发布"的正确姿势

1. 先看 `release_gate.passed`
2. 若为 false，看 `failed_gates` 列出哪几道没过
3. 独立复算单独看 `verification.pass` 与 `mismatch_count`

不要因为"复算通过了"就说"可以发布了" —— 那只过了三道门禁中的第一道。

## 证据链

每次运行会签封证据（`S09_seal_evidence`），
`report/report_manifest.json` 记录报告与证据文件的路径和哈希，
用于事后追溯"这个结论当时依据的是哪份输入、哪版规则"。
