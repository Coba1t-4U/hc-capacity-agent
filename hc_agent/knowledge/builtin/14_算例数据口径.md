# 算例数据口径与规模

协同调度与承载力的算例都由一批标准化的表格构成。认不清这些表，
就无法核对结论是怎么来的。

## 省级主配协同算例的规模（配套数据包实测）

| 项目 | 规模 | 说明 |
|---|---|---|
| 时序 | t1 ~ t48 | 48 个时间断面（不是 24，注意别按 24 小时想当然） |
| 节点 | 1082 个 | 含发电机节点、负荷节点与其他节点 |
| 支路 | 1173 条 | 含线路与变压器等值支路 |
| 风电场 | 2 个 | 各自有独立风速曲线 |
| 光伏设备 | 39 个 | 用同一组归一化出力曲线 |
| 母版负荷曲线 | 7 条 | 归一化后按比例分配给各负荷节点 |

### 各表的作用

| 表 | 内容 |
|---|---|
| 时序表 | t1~t48 对应 0 点起的逐时段数据 |
| 风光出力表 | 风电、光伏的时序有功出力（单位 MW） |
| 风速曲线表 | 2 个风电场的时序风速（单位 m/s） |
| 光照曲线表 | 39 个光伏设备的归一化出力时序 |
| 节点参数表 | 1082 个节点的总体数据（发电机/负荷类型、风光挂接位置、负荷时序、时序电压） |
| 支路参数表 | 1173 条支路的总体数据（首节点时序潮流 P/Q，单位 MVA） |
| 母版曲线表 | 7 条母版负荷归一化曲线 |

### 两个容易踩的坑

1. **节点表里"gp=0 是发电机节点、p≠0 是负荷节点"** ——
   判类型看的是字段值，不是名字。
2. **节点电压 v1~v48 是"经时序潮流分析后得到的结果"**，
   不是输入。校对时要分清哪些列是输入、哪些是输出。

## 三微网协同算例（目标级联 + 分布鲁棒）

配套的 MATLAB 算例是一个**配网 + 3 个微网**的分层结构：

| 层级 | 模型文件 | 说明 |
|---|---|---|
| 上层 | `distribution.m` / `distribution2.m` | 配电网优化，含碳/燃料价格、储能 |
| 下层 1 | `matou.m` / `matou2.m` | 码头微网 |
| 下层 2 | `xuexiao.m` / `xuexiao2.m` | 学校微网 |
| 下层 3 | `nongzhuang.m` / `nongzhuang2.m` | 农庄微网（含 ORC 余热发电） |
| 协调 | `mainATC1.m` / `mainATC2.m` | 目标级联迭代 |
| 参数 | `parameterATC.m` | 罚函数、收敛阈值、价格系数 |
| 数据 | `dataMG1.m` ~ `dataMG3.m` | 各微网的源荷储参数 |

### 微网设备参数的量级（`dataMG1.m` 实测）

| 参数 | 取值 | 含义 |
|---|---|---|
| `Pmax` / `Pmin` | 3 / 0.5 | 机组出力上/下限（MW 量级） |
| `rg` / `re` | 0.5 / 1 | 爬坡率上/下限 |
| `capmax` / `capmin` | 2 / 0.2 | 储能容量上/下限（MWh 量级） |
| `EESmax` / `EESmin` | 0.15 / 0.05 | 荷电状态上/下限 |
| `num_chmax` / `num_dismax` | 20 / 20 | 每日充/放电次数上限 |

荷电状态只在 0.05 ~ 0.15 之间用，说明储能配置很小、只做短时调节，
不是用来做大范围移峰的。这一点会影响"储能能否缓解承载力"的判断。

## 与本工程产物字段的对应

本工程每次运行产出的都是**本项目模型格式**的产物
（`constraint_results.csv`、`capacity.csv`、`run_summary.json` 等），
与上面那套研究算例**不是同一套数据**。

引用关系要写清：

- 研究算例（1082 节点 / 三微网）用于**方法验证**；
- 本工程产物用于**工程结论**。

两者不可混用，尤其不能拿研究算例的容量数字当成本工程的结论。
