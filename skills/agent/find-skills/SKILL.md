# 找技能（find-skills 的本工程版）

原版 `find-skills`（vercel-labs）依赖 `npx skills` 联网检索生态里的技能。
**本工程是离线桌面应用**，打包后没有 Node、也禁止联网，
所以这里做成**本地清单检索**：在已有的技能卡与契约里找，找不到就说找不到。

## 什么时候用

- 用户问"有没有办法做 X""能帮我做 X 吗""有没有相关技能"
- 用户想知道"这个系统能做什么"
- 用户想扩展能力（"能不能加个功能"）

**不适用**：用户已经在描述具体任务（直接做就行，不用先找技能）。

## 检索范围（按顺序查）

### 1. 技能卡 `skills/cards/SK-*.md`（人读）

| 编号 | 名称 | 解决什么 |

| SK-01 | 拓扑与模型一致性检查 | 网架/相别/版本对不对 |
| SK-02 | 负荷与光伏曲线标准化 | 曲线单位、时间戳、插值 |
| SK-03 | 运行场景生成 | 场景集怎么选 |
| SK-04 | 基线潮流计算 | 当前状态算一遍 |
| SK-05 | 增量接入潮流计算 | 接入后的变化 |
| SK-06 | 电压越限校核 | 电压合不合格 |
| SK-07 | 载流与反向潮流校核 | 设备过载、倒送 |
| SK-08 | 三相不平衡校核 | 不平衡度 |
| SK-09 | 短路容量与保护触发 | 短路电流超没超 |
| SK-10 | 开放容量搜索 | 还能接多少 kW |
| SK-11 | 并网申请方案校核 | 这个申请行不行 |
| SK-12 | 独立复算与证据链 | 复算对不对、证据全不全 |
| SK-13 | 整改建议候选 | 越限了怎么办 |

### 2. 技能契约 `skills/contracts/*/skill.json`（机读）
可被执行、受权限管控的那一层。目前 5 个：
`HC.REMEDIATION.PROPOSE`、`HC.REMEDIATION.FROM_RUN`、`HC.AUDIT.VERIFY`、
`HC.CALIBER.BINDING`、`HC.ACCEPTANCE.MATRIX`。

区别：**技能卡是文档，技能契约能真跑**。用户问"能不能执行"时看契约。

### 3. 知识库 `hc_agent/knowledge/builtin/`（31 篇）
不是"技能"，但很多问题是知识型问题，这里能答。按主题检索。

### 4. 内置工具（给大模型用的函数）
`hc_agent/llm.py` 的 `TOOLS`，12 个：容量、约束、电压、接入校核、
复算、门禁、运行列表、算例分析、算例内部清单、增减假设、限值、边界。

## 输出格式

**找到时**：

```
有，SK-10「开放容量搜索」正是做这个的。
它需要：<输入>
产出：<输出>
调用方式：<在问答里怎么问 / 或者走哪个页面>
```

**找不到时**（这条最重要）：

```
本工程的技能清单里没有直接对应的能力。
最接近的是：<最接近的那个>，但它只做 <…>，不覆盖 <你要的那部分>。

有两个选择：
1. 我用现有的 <某能力> 尽量做，但要说明局限：<局限>
2. 新建一个技能。做法：<三步>
```

**不许**编一个不存在的技能编号糊弄过去。

## 自建技能的做法

1. **写技能卡**：`skills/cards/SK-18_HC_XXX.md`
   固定顺序：目的—适用范围—输入—前置条件—执行步骤—输出—异常—证据—边界—测试样例。
   步骤里**不许出现"适当、合理、必要时"**这种没法验收的词。
2. **能执行就写契约**：`skills/contracts/HC.XXX/skill.json`
   ```json
   {
     "id": "HC.XXX.YYY", "version": "1.0.0", "skill_code": "SK-18",
     "display_name": "...", "description": "...",
     "actions": ["<动作名，必须在 policy.ACTION_LEVELS 里登记>"],
     "handler": "hc_agent.<模块>:<函数>",
     "permission": "read_only | offline_simulation | candidate_generation",
     "requires": ["<必需输入>"], "outputs": ["<产出>"],
     "auto_enabled": false
   }
   ```
3. **登记动作权限**：在 `hc_agent/policy.py` 的 `ACTION_LEVELS` 里加一行，否则加载会报错。
4. **写测试**：在 `tests/` 加断言。

## 硬规则

- **优先用现有的**。能组合就别新建。
- **找不到就直说**，不要拿一个名字像的技能冒充。
- **技能卡与契约要配套**：只写卡不写契约 = 人读得到、机器调不了。
- **动作必须登记权限**，否则默认拒绝 —— 这是刻意的安全设计。
