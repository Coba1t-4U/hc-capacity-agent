# HC.AUDIT.VERIFY@1.0.0  审计链校验

**目的**：回答"这份运行结果有没有被改动过"，为结论的可追溯性提供可检查的证据。

**适用范围**：全部业务场景；只读技能；任意权限级别（含 L0 只读）。

**是否必须专业引擎**：否

**输入**：
- `run_dir`（路径）（必填）某次运行的目录

**前置条件**：
- 该运行目录存在
- 已有 `audit/chain.jsonl`（没有则提示可补建）

**执行步骤**：
1. 逐行读取 `audit/chain.jsonl`。
2. 对每条记录按固定字段集重算 sha256，与记录里的 `event_hash` 比对。
3. 检查 `previous_hash` 是否等于上一条的 `event_hash`。
4. 任一处不一致即判定断开，给出**第一条**断开的序号与原因。

**输出**：
- `ok`（布尔）、`count`（条数）、`broken_at`（序号或 None）、`reason`、`head_hash`

**异常**：
- 某行不是合法 JSON → 视为被改动或截断，`broken_at` 指向该行。
- 日志为空 → `ok=true, count=0`（空不等于被篡改）。

**证据**：链头 `head_hash` 写入回答，便于对外核对。

**边界**：
- 校验的是**记录完整性**，不是**结论正确性**。结论正确由独立复算与人工审批负责。
- 不修改任何原有事件文件；补建链写在新文件 `audit/chain.jsonl`。
- 补建链本身也应记一条事件，否则等于"事后补的记录没有痕迹"。

**测试样例**：
| 场景 | 期望 |
|---|---|
| 正常 5 条 | `ok=true, count=5` |
| 改第 3 条的 detail | `ok=false, broken_at=3`，原因含"内容被改过" |
| 删掉中间一条 | `ok=false`，原因含"previous_hash 不匹配" |
| 坏 JSON 行 | `ok=false`，原因含"不是合法 JSON" |
| 没有链 | `ok=false`，提示可补建 |
