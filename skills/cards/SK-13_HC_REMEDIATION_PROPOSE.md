# HC.REMEDIATION.PROPOSE@1.0.0  整改建议候选

**目的**：当承载力结论是"不能再接"时，给出**候选整改方向**，让用户知道下一步能做什么。

**适用范围**：业务场景 capacity_assessment / remediation_review；对象层级 dt / feeder；
状态 approved；权限要求 **候选生成（L2）**。

**是否必须专业引擎**：否（本技能只给方向，不算改造后的容量）

**输入**：
- `binding_constraint`（-）（必填）绑定约束名
- `voltage_violations` / `overloaded`（-）越限明细（可选，用于精确触发）
- `voltage_margin` / `loading_margin`（pu / %）（可选）约束裕度

**前置条件**：
- 已有一次完成的约束校核结果（至少知道哪条约束越限）
- 权限级别 ≥ 候选生成

**执行步骤**：
1. 读取绑定约束与越限明细，逐条判断哪类约束**真的被触发**。
2. 只为触发了的约束匹配候选库条目（没越限的约束不出方案）。
3. 每条候选输出四要素：为什么、效果、局限、依据。
4. 附免责声明：本版不计算改造后容量、不做经济性比较。

**输出**：
- `candidates[]`：每条含 `id` / `title` / `constraint` / `why` / `effect` / `limits` / `basis`
- `disclaimer`（必带）

**异常**：
- 未给绑定约束且无越限明细 → 返回 `count=0`，并说明"需要先知道哪条约束越限"。
- 绑定约束不在候选库中 → 给一条"需专项分析"的兜底候选，**不凭猜测编方案**。

**证据**：候选库条目编号（如 `RM-V-01`）与依据文献名称写入回答。

**边界**：
- **不**给出改造后的承载力数字（需重新建模 + 容量搜索）。
- **不**做经济性比较（另见《经济性与投资评估》）。
- **不**做设备选型。
- 候选是"方向"，不是"结论"，必须经专业设计与人工审批。

**测试样例**：
| 输入 | 期望 |
|---|---|
| `binding_constraint=VOLTAGE_LIMIT` | 命中 RM-V-01/02/03 |
| `binding_constraint=THERMAL_LIMIT` + `overloaded` | 命中 RM-T-01/02 |
| 电压与载流同时越限 | 两类候选都给 |
| 无任何越限 | `count=0` |
| 权限只有 L1 | 抛 `PolicyViolation`（越权是错误，不是空结果） |
