# 拖入资料与算例内部问答

两块新能力：**把压缩包/文档拖进对话** 和 **对算例内部提问**。

---

## 一、拖入资料

对话页输入框上方有一条提示：`⬇ 把压缩包 / 文档 / 算例拖到这里，或 选择文件…`

支持拖入的东西与处理方式：

| 拖进来 | 处理 |
|---|---|
| `.zip`（压缩包） | 抽出 md/txt/csv/docx/pdf/xlsx 的正文入知识库；含 `.dss` 就解出算例并登记 |
| 单个文档 | 抽正文入知识库 |
| 文件夹 | 里面有 `.dss` 当算例登记；里面的文档批量入库 |
| `.dss` 文件 | 把它所在目录登记成算例 |

入库位置是一个叫 **「拖入资料」** 的知识库（第一次用到时自动创建）。

### 结果会如实列出三类

```
已处理拖入内容

已导入知识库 2 篇；登记算例 1 个；跳过二进制/不支持 1 个。

压缩包：参考资料.zip　→ 已登记算例：C:\...\dss_dropped\参考资料\case
· 入库：电压偏差.md（420 字）、不平衡.md（388 字）
· 未入库：扫描件.pdf（抽不到正文）
· 跳过（不可作知识）：tool/run.exe
```

**不会只说一句"完成"**：导入了什么、哪篇抽不到正文、哪几个是二进制被跳过，
全部列出来。抽不到正文（扫描版 PDF、加密文档）会进"未入库"并给出原因，
不会当成空文档塞进库。

### 拖放是怎么实现的

Windows 原生拖放（`WM_DROPFILES`），不用第三方库：

1. `DragAcceptFiles(hwnd, True)` 让窗口接收投放
2. `SetWindowLongPtrW(GWLP_WNDPROC, ...)` 接管窗口过程，在 `WM_DROPFILES` 里取路径
3. 路径进队列，主线程轮询后处理

**这个过程踩过一次会闪退的坑**：第一版没有给 Win32 调用声明 `argtypes`，
`CallWindowProcW` 把原窗口过程当成 32 位整数传入，64 位下立刻访问违例、
进程直接消失（界面挂上拖放后几秒内闪退）。现在每个调用都显式声明类型，
并且长期持有窗口过程的引用（被 GC 掉同样会崩）。

**拖放失败会自动降级**：如果系统层面挂不上（权限/远程桌面等），
「选择文件…」按钮仍然可用，走完全相同的处理逻辑。

## 二、算例内部问答

以前只能问"算完的结果"（还能接多少、哪里越限）。现在可以直接问**算例本身**：

| 问法 | 回答内容 |
|---|---|
| 这个算例里有什么元件 | 线路/配变/负荷/电源清单，含参数（长度、变比容量、功率因数） |
| 线路有多长 / 配变多大 | 同上，从 `.dss` 文本里解析 |
| 光伏接在哪几个点 | 每处电源的容量与接入母线，附与本地负荷的对比 |
| 如果把光伏加到 300 kW 会怎样 | **真的改一份副本重跑引擎**，给改造前后对比 |

### 数据从哪来（分工明确）

- **静态元件**：直接解析 `.dss` 文本（会自动展开 `Redirect`，否则会漏元件）
- **计算结果**：交给 OpenDSS 引擎（电压、负载率、网损）
- 两者不混用：静态解析不猜电气结果，引擎结果也不反推元件参数

### 假设分析不是外推

问"加到 300 kW 会怎样"时，实际做的是：

```
复制算例到临时目录 → 按原容量比例改每个 Generator 的 kw → 重跑潮流 → 前后对比
```

所以给的是真算出来的数（例：`配网承载力算例_双台区对比` 光伏 220→300 kW，
最高电压 1.1317→1.2004 pu），而不是按比例估的。**原算例不会被改动**，
界面上也会明确说这一点。

### 大模型也能用

给 DeepSeek 加了两个工具：

- `inspect_dss_case`（`what=inventory|pv`）
- `what_if_dss_case`（`target_kw`）

系统提示里明确：问"算例里有什么"时**不要**去跑 `analyze_opendss_case`，
那会白跑一次潮流并生成报告。

## 四、踩过的坑（都已修）

1. **`CallWindowProcW` 没声明 argtypes → 进程闪退**（上面详述）
2. **工作线程里调 Tk**：`post_drop` 里写了 `self._alive()`，
   跨线程调用导致结果永远不渲染。改成"线程只碰队列，主线程轮询"。
3. **`ChatPage` 不是 Tk 控件**：`self.after(...)` 直接 AttributeError
   （`'ChatPage' object has no attribute 'after'`），必须 `self.view.after(...)`。
   同类问题此前在 `tk.Menu(self)` 上已经踩过一次。
4. **`pages.py` 漏 `from pathlib import Path`**：`handle_drop` 一进来就 NameError，
   被外层 `except` 吞掉，表现为"拖了什么都没发生"。这类漏导入已经是第二次，
   建议把"未定义名字"检查做进 CI。
5. **压缩包里的算例在子目录**：一开始按顶层找 `.dss`，`case/Master.dss` 这种
   就登记不上。改成解压后定位真正含 `Master.dss` 的那一层。
6. **`create_kb()` 返回 `{"ok":…, "kb":{…}}`**：直接取 `["id"]` 会 KeyError。
