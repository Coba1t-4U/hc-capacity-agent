## 二、三种使用方式

### 方式 A：先添加算例，再让问答算（推荐）

1. 「问答」页 → 输入框右侧点 **「＋ 添加算例」**
2. 选「选择算例目录」或「选择 .dss 文件」
3. 添加成功后，输入框上方出现 **已添加算例** 胶囊
4. 直接说，或**点那个胶囊**：

```
算一下我加的算例，并给我计算报告
```

5. 回答里出现 **「打开计算报告」** 按钮，点开就是 Word 报告

添加算例**不复制文件**，只记录它在你磁盘上的位置。所以你改完 `PV.dss`
里的 `kw=` 再问一次，就按新参数重算，不用重新添加。

### 方式 B：直接说路径

```
算一下桌面上的 OpenDSS 算例，并给我计算报告
分析 C:\Users\Chen\Desktop\配网承载力算例_光伏高渗透
```

不指定路径时，会依次找：桌面默认算例 → 已添加算例里最近的一个。

### 方式 C：走「算例分析」页

左侧导航「算例分析」→ 选文件/目录 → 「分析」。
这一页多了母线电压表、支路负载表、越限明细三个标签，适合逐项核对。

## 三、报告里有什么

`<数据目录>/dss_runs/<算例名>_<时间戳>/` 下：

| 文件 | 内容 |
|---|---|
| `report.docx` | Word 报告，7 节 |
| `report_manifest.json` | 报告清单：路径、哈希、章节、引擎版本 |
| `summary.json` | 结构化结果，供问答与后续引用 |

报告 7 节：

1. **口径声明** —— 明确写"原生算例分析，不产出开放容量"
2. 求解概况 —— 收敛、迭代、母线/支路数、耗时
3. **功率平衡** —— 负荷、分布式电源、源侧交换、网损（附关系式）
4. **电压结果** —— 最高/最低电压及位置、越限母线明细
5. **设备负载** —— 最大负载率元件、过载明细
6. **结论要点** —— 哪个约束先被顶到（每条都基于实测）
7. 全量明细 —— 母线电压表、支路负载表

## 四、为什么"不产出开放容量"

原生算例分析只做**一个稳态断面**的潮流与约束校核。
开放容量（承载力）需要容量搜索（梯度/二分）、经批准的规则包、
场景派生与独立复算 —— 那是针对本项目模型格式的流程。

把外部 `.dss` 直接套上容量搜索会得到**看似权威但口径不成立**的数字，
所以本工程明确不做，并在报告与回答里都写清这一点。

## 五、做这件事时修掉的 6 个真 bug

1. **`CalcVoltageBases` 顺序错** → 母线 `kVBase=0` 时引擎返回的是**伏特不是标幺值**
   （6166 而非 1.017），所有电压判据失效。现已在引擎代码里加防呆：
   检测到 0 就补算并告警。
2. **支路功率只取 A 相** → 少算 2/3。
3. **变压器两端子功率相互抵消** → 220 kW 的线路只算出 10 kW，变压器只剩损耗。
   改为只取**送端**。
4. **网损公式在反送时失效** → `|源侧| − 负荷` 把倒送功率算进损耗
   （真实 15.7 kW 算成 34.3 kW、损耗率 40%）。改为**能量平衡**：
   源侧供给 + 分布式电源 = 负荷 + 网损。
5. **`Toplevel(self)` 挂在 Frame 上** → 对话框模态与定位异常。
   改为挂顶层窗口。
6. **后台回调把聊天记录清空** → 后端每次回调都整页 `_render_page()`，
   把 ChatView 重建，消息全丢（提问后几秒"消息突然消失"）。
   新增 `Page.STATEFUL`，问答/算例/知识库/配置页不再被整页重建。

修完后 IEEE13（网损 101.02 kW / 2.91%）、IEEE37（131.32 kW / 5.34%）
与之前独立验证过的数字**完全一致**，说明没有破坏已有正确性。

## 七、已知限制

1. **只做单断面**（`snapshot` 模式），不做时序、不做 24 小时曲线。
2. **不做容量搜索**，所以没有"还能接多少 kW"的结论。
3. **依赖 OpenDSS 引擎**；引擎不可用时如实报错，不降级估算。
4. 报告为 Word 格式；若环境缺 `python-docx` 会自动退化为 Markdown。
5. 算例目录被移动/删除后，登记表里的条目会标为「已失效」，
   需要重新添加（不会静默失败）。
