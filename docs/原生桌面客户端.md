# 原生桌面客户端

> `hc_agent/desktop/` —— **原生桌面程序，不是网页**
> 启动：双击桌面「配网承载力 Agent」，或 `hc_agent_ui\start-native.bat`

## 一、为什么是"原生"而不是"套壳浏览器"

先前做过一版 Electron 壳，界面本质上仍是 Chromium 在渲染 HTML，数据还要经过
一个本地 HTTP 服务。那不算桌面端，只是"带窗口的网页"。现在这一版：

| 维度 | Electron 壳（旧） | 原生客户端（现） |
|---|---|---|
| 界面渲染 | Chromium 渲染 HTML/CSS | **Tk 原生控件** |
| 数据传输 | 本地 HTTP（端口 8791） | **stdin/stdout 管道上的行分隔 JSON** |
| 浏览器引擎 | 有（约 180 MB） | **无** |
| 监听端口 | 有 | **无** |
| 界面定义 | `index.html` + `styles.css` + `app.js` | `pages.py`（Python 构造控件） |

`tests/verify_desktop.py` 会静态校验桌面端**不含** HTML 标签、不导入
`http`/`urllib`/`socket`、不含端口常量 —— 这条约束是写进测试的，不是口头承诺。

## 二、架构：为什么引擎必须在子进程里

```
桌面端 (Tk GUI)  ──spawn/监督/必要时重启──▶  engine_host  ──▶  OpenDSS
     主进程                                        子进程
```

**这是被看门狗的契约逼出来的**：看门狗判定"引擎中毒"时会 `os._exit(70)`
请求外层重启。线程卡在原生调用里时 Python 无法强杀它，只有**进程边界**能清理
资源。如果引擎跑在 GUI 进程内，那个退出会把**整个界面**一起带走 —— 界面消失得
毫无痕迹，比不退出更糟。

所以桌面端自己就是那个"外层重启者"：
* 监听子进程退出码 70 → 提示"检测到计算引擎异常，正在自动恢复…" → 重启后端；
* 其他非零退出码 → 提示"后端进程意外退出（退出码 X），正在重启…"（**措辞必须
  区分**，否则用户以为程序出错）；
* 重启前等 1.2 秒让旧进程释放 OpenDSS 句柄；
* **重启风暴熔断**：60 秒内超过 4 次就停下并说清去哪看日志 —— 继续重启只会让
  界面永远转圈。

## 三、通信协议（无 HTTP）

请求：`{"cmd": "<name>", "args": {...}, "tag": "<唯一串>"}`
应答：`{"kind": "result", "tag": "<同串>", "ok": true, ...}`
就绪：`{"kind": "ready", "channel": "...", "diagnostics": {...}}`

`engine_host.py` 的 stdout **只允许**协议行；任何库的 `print` 都会被父进程当成
普通日志转走，所以那个文件里不允许有裸 `print`（日志一律走 stderr）。

命令：`ping` / `diagnostics` / `channels` / `runs` / `run_detail` /
`run_task` / `read_text` / `shutdown`。

### 一个踩过的并发坑

最初让所有调用者共享一个结果队列、各自挑走自己的应答，不匹配就放回去。但主线程
的 `drain()` 会把"放回去的消息"当成无主消息丢掉 —— 于是三个并发请求里只有最先
发的那个能成功，其余全部静默超时。

现在改成 **tag → 该请求专属队列** 的登记表（`_waiters`），应答按 tag 直接投递给
发起者。`verify_desktop.py` 用"三个并发请求必须全部成功"钉住这个行为。

## 四、界面

三个页面、十一个子页，全部由 Tk 控件绘制：

| 页面 | 子页 |
|---|---|
| **运行总览** | 环境与就绪度 · 可靠性设施 · 引擎通道 · 运行记录 |
| **容量分析** | 发起评估 · 算例与场景 · 约束与阈值 |
| **结果与证据** | 容量结论 · 求解口径声明 · 证据链与门禁 · 独立复算 |

**桌面端比只读看板多出的能力**：能在「容量分析」页选输入/输出目录并**真正发起
一次评估**。任务在子进程里跑，界面保持可用。

视觉沿用同一套设计令牌（与 `static/styles.css` 同源，测试会校验两边一致）。
Tk 没有圆角和阴影，层次感靠「白底卡片 + 1px 极浅描边 + 留白」建立。

## 五、无边框窗口

`overrideredirect` 去掉系统边框后，必须自己实现三件事，否则窗口既拖不动也关不掉：

1. **拖动**：绑定标题栏的 `<Button-1>` / `<B1-Motion>` 自己算位移；
2. **三个窗口按钮**（最小化/最大化/关闭）：自绘 Label + 悬停变色，关闭键悬停变红；
3. **最大化**：记住还原尺寸，切换时复位。

另外必须声明 **DPI 感知**（`SetProcessDpiAwareness`），否则高分屏上界面会被系统
拉伸成糊的。

## 六、踩过并修掉的坑

| 问题 | 现象 | 修法 |
|---|---|---|
| **正常启动时内容区全空白** | 只有导航和状态栏，右侧一片白 | `_boot()` 里无条件 `show()` 首页；此前只在深链存在时调用 `show()`，`self.page` 一直是 None |
| **结果页永远为空** | 口径声明显示"未包含"，明明有产物 | `_load_all()` 补上自动载入一次运行明细 |
| **并发请求静默超时** | 三个请求只成功一个 | tag → 专属队列的登记表 |
| **`start "" /b` 让应用随控制台退出** | 双击后窗口一闪即逝 | 去掉 `/b`，子进程独立于启动控制台 |
| **`NameError: CARD`** | 打开"运行记录"页就崩 | `T.CARD`（并加了静态未定义名检查） |
| **标题匹配抓错窗口** | 截图抓到 DSH 而不是本应用 | DSH 标题里含"配网承载力"（设计文档文件名），必须**精确**匹配 |
| **口径表"场景覆盖"说明显示"可行"** | 牛头不对马嘴 | 误把接入校核结论 `decision_candidate` 当成场景说明；改为场景类别 |
| **"未获取 kW"** | 读起来像单位缺失 | `fmt_unit()`：缺失时只显示「未获取」，不拼单位 |

## 七、验证

```
python tests/verify_desktop.py     # 55 项：原生性 / 设计令牌 / 协议 / 并发 / 渲染 / 启动器 / 数据诚实
python tests/check_names.py        # 18 项：静态检查未定义名（NameError 类 bug）
python tests/verify_launcher.py    #  2 项：启动器真的能拉起窗口，且 GUI 与引擎各一个进程
```

`verify_desktop.py` 会逐个打开 **11 个子页并统计控件数** —— 内容区空白是这类
应用最隐蔽的故障，只截导航栏的图是看不出来的。

## 八、已知限制（不夸大）

* **不打包成单个 exe**：依赖本机 Python 运行时（含 Tk）。要独立分发需另用
  PyInstaller 之类工具，本版未做。
* **Tk 无圆角/阴影/动画**：视觉上比网页版朴素，这是控件的固有限制，不是没做。
* **`read_text` 限制 8 MB**：报告过大时请直接打开文件，避免界面卡顿。
