# DeepSeek 接入与 API Key 配置

## 一、当前状态

**已接入并验证通过**：源码版与打包版都能读到 Key，真实调通。

| 位置 | 数据目录 | 状态 |
|---|---|---|
| 源码运行 | `hc_agent_project/` | ✅ 已配 Key |
| 打包运行（桌面快捷方式） | `%LOCALAPPDATA%\HC-Agent\` | ✅ 已配 Key |

两处如何确认：

```powershell
# 源码版
python -m hc_agent --llm-test

# 打包版
dist\HC-Agent\HC-Agent.exe --llm-test
```

输出里 `"reachable": true` 即表示 Key 有效且网络可达。
界面右下角也会一直显示 `当前：DeepSeek · sk-15b…f730`，
每条回答的气泡上还有 `DeepSeek` 或 `本地规则` 的徽标。

## 二、Key 存在哪、怎么找

配置文件是 `llm.json`：

```json
{
  "api_key": "sk-...",
  "base_url": "https://api.deepseek.com",
  "model": "deepseek-chat"
}
```

### 多路径查找（重要）

读取时按优先级依次尝试，**任一位置有有效 Key 就生效**：

1. 主数据目录：`%LOCALAPPDATA%\HC-Agent\llm.json`（打包版）或项目根（源码版）
2. 降级目录：数据目录不可写时的回落位置
3. 用户家目录兜底：`~/.hc-agent/llm.json`

写入时**双写**到上述所有可写位置。

为什么必须这样：`data_root_safe()` 在数据目录不可写时会**降级**到别处
（沙箱、只读安装目录、权限受限的用户目录都会触发）。
如果只认固定路径，就会出现"打包版把 Key 写在 AppData，
读的时候却跑去看降级目录，于是认为没配置" —— 实测踩过：
源码版显示 DeepSeek，打包版仍显示本地规则引擎。
（另外当时 `llm.py` 漏了 `Path` 导入，家目录兜底分支被 `except` 静默吞掉，
这也是"静默失败"要格外小心的原因。）

### 环境变量优先

临时切换用环境变量，优先级最高：

```powershell
$env:DEEPSEEK_API_KEY = "sk-..."
$env:DEEPSEEK_MODEL   = "deepseek-chat"      # 可选
$env:DEEPSEEK_BASE_URL= "https://api.deepseek.com"   # 可选
```

## 三、怎么重新填 Key

### 界面

「问答」页 → 右下角 **「模型设置」** → 填 Key → **「测试连接」** → **「保存」**。
「配置」页 → 「模型接入」也能看到当前状态与测试按钮。

### 命令行

```powershell
python tools/install_api_key.py sk-你的Key
```

### 手动

直接把上面那份 `llm.json` 放到数据目录即可。

## 四、设计上的两条硬规矩

**1）数字只能来自本地工具，模型不得自己算**

```
用户问题 ──▶ DeepSeek ──(决定查什么)──▶ 本地工具 ──(读真实产物)──▶ 数据
                 ▲                                              │
                 └──────── 只允许复述工具返回值 ◀───────────────┘
```

系统提示里明确禁止模型自行计算、推算、估算或补齐数值。
实测效果：问"FD002 还能接多少"，模型回答 333.98 / 270.53 kW，
与产物逐位一致，并主动补了一句"上述是确定性（单场景）口径"。

**2）知识库只提供方法说明，不提供实测数字**

检索到的知识作为补充上下文注入，并明确要求不得引用其中的示例数字 ——
否则知识里写死的旧数值会污染实时结论。

## 五、失败时的行为

DeepSeek 不可用（无 Key / 网络不通 / 限流 / 5xx）时：

- **自动退回本地规则引擎**，用户仍能得到回答；
- 回答上方给出明确提示：`⚠️ DeepSeek 不可用，本回答由本地规则引擎生成。原因：…`；
- 界面徽标变为 `本地规则`，底部显示"当前：本地规则引擎"。

**不会**静默降级 —— 用户有权知道这条回答是谁给的。

429 / 5xx 是瞬时故障，会先自动重试 2 次（间隔 0.8s、1.6s）再退回；
401/402/403 属于配置或余额问题，不重试，直接如实报错。

## 六、安全说明

- Key **明文存在本地** `llm.json`，这是桌面单机应用的常规做法，
  未做额外加密；保护依赖系统账户权限。界面上会如实告知这一点。
- Key 在界面上只显示掩码（`sk-15b…f730`），不会完整回显。
- 打开的"计算报告"只允许报告类扩展名（docx/md/html/pdf/txt/csv），
  防止模型输出被当成"打开任意文件"的能力。

## 七、验证

`tests/verify_api_key.py` —— **27 项**，覆盖：

- 真实配置到位、Key 形态、模型名、接口地址
- **真实连通性**（会真的发一次最小请求）
- 多路径查找（主目录没有时能从兜底位置读到）
- 环境变量优先于文件
- 双写：保存后清掉环境变量、只靠文件仍能读到
- 无 Key 时退回规则引擎、给出明确提示、回答诚实（没数据就说没数据）
- `--llm-test` 开关可用且输出可解析
- 界面能看出当前走的是哪个引擎
