# 问答会话管理

问答页做成"左侧会话列表 + 右侧对话"的形态，对齐常见聊天应用：
可以开新会话，也可以点任意一条历史会话把当时的内容翻回来。

## 一、布局

```
┌──────────────┬──────────────────────────────────────────┐
│ ＋ 新会话     │  （对话区）                               │
│              │                                          │
│ 历史会话      │   你：为什么容量是 0？                    │
│ ▸ 电压越限…  2│                                          │
│   算一下我加… 2│   承载力 Agent [DeepSeek]                 │
│   为什么容量… 2│   电压约束的判据是…                       │
│              │   [打开计算报告]                          │
│              │                                          │
│ [删除该会话]  │  （输入区）                               │
└──────────────┴──────────────────────────────────────────┘
```

- **＋ 新会话**：开一段干净的对话，对话区清空并给出引导语
- **历史会话**：按最近更新时间倒序；当前会话高亮；右侧数字是消息条数
- **点一下会话**：把当时的消息回放出来
- **删除该会话**：删掉当前会话及其全部消息（二次确认）

## 二、标题怎么来

不用先起名字：**第一条提问自动成为会话标题**（截断 28 字）。
想改名可以调 `ChatHistory.rename()`；界面暂未提供改名入口（见"已知限制"）。

## 三、回放要还原"当时的样子"

这是这块最容易做错的地方。只存纯文本的话，历史消息会"比当时少了东西"：

| 存了 | 回放效果 |
|---|---|
| `content` | 气泡正文 |
| `engine` | 气泡上的 `DeepSeek` / `本地规则` 徽标 |
| `source` | 出处（产物相对路径） |
| `report_path` + `report_label` | **「打开计算报告」按钮** |

所以 `message` 表这五个字段都要存，`ChatView.replay()` 逐条还原。
不做这一步，用户翻回历史会以为记录不完整。

## 四、存储

独立的 SQLite：`<数据目录>/chat.sqlite`

```
session(id, title, created_at, updated_at)
message(id, session_id, role, content, engine, source,
        report_path, report_label, created_at)
```

**为什么不并进知识库那套 `kb.sqlite`**：语义完全不同，
放一起会让"删知识库"和"删会话"互相牵连。分开更安全。

### 时间戳带微秒

`updated_at` 用微秒精度。秒级精度会出问题：新建会话后立刻发消息，
两条时间戳落在同一秒，`ORDER BY updated_at DESC` 退化成任意顺序 ——
表现是"刚发的会话不在最上面""重开应用选错会话"（实测踩过）。

## 五、代码用法

```python
from hc_agent.chat_history import ChatHistory

h = ChatHistory()                 # 默认 <数据目录>/chat.sqlite
s = h.ensure_session()            # 有最近会话就沿用，没有就新建
h.add_message(s["id"], "user", "FD002 还能接多少光伏？")
h.add_message(s["id"], "assistant", "物理 333.98 kW…",
              engine="deepseek:deepseek-chat", source="runs/FD002")
h.list_sessions()                 # 带 msg_count，按更新时间倒序
h.list_messages(s["id"])          # 回放用
h.rename(s["id"], "容量疑问")
h.delete(s["id"])
```

## 六、做的时候踩到的坑

**`self._history` 命名冲突（消息全部没落库）**

`ChatView` 里 `self._history` 已经被"输入框 ↑ 键历史"占用。
我一开始把 `ChatHistory` 也存到 `self._history`，赋值后立刻被
`self._history = []` 覆盖成列表 —— 于是每次落库都 `AttributeError`，
又被 `except Exception: return` 静默吞掉。现象是：对话正常，
但会话条数永远是 0、切换会话什么也没有。

修法：数据库用独立属性 `self._db`；并且落库失败时**打到 stderr 留痕**，
不再静默。

教训：**同一个类里给"外来对象"起名，务必避开已有字段名**；
`except` 里至少要留一条可查的痕迹。

## 七、已知限制

1. **不支持改名**（接口有 `rename`，界面没做入口）。
2. **不支持搜索历史会话**（列表只有最近 60 条）。
3. **不支持导出**（可后续加"导出为 Markdown"）。
4. 会话列表不分组、不置顶、不加星标。
5. 删除会话不做软删除，删了就是删了（有二次确认）。

## 八、验证

`tests/verify_sessions.py` —— **45 项**：

- 存储层：建会话、自动标题、消息增删、引擎/出处/报告路径都保留
- 列表倒序、消息条数、`ensure_session` 复用最近会话
- 改名、删除（连带消息）、清空消息保留会话
- 重开实例仍能读到（真持久化）
- 界面接线：新会话按钮、历史列表、切换、删除、回放
- **回归**：持久化用 `self._db`，不得再用 `self._history`（防命名冲突复发）
- 运行时：两个会话独立落库 2 条、新会话清空、切回各自回放正确
