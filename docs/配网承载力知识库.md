# 配网承载力知识库系统

> 模板参考：[ai-localbase](https://github.com/veyliss/ai-localbase)（本地优先 RAG）
> 本工程按它的**系统形态**实现，换成纯离线、单进程内嵌（原生 Tk 桌面）。

## 一、这是一个"系统"，不是"一堆文档"

照模板实现了完整的知识库能力面：

| ai-localbase | 本实现 | 位置 |
|---|---|---|
| 知识库管理：建/删、查看文档列表 | 多知识库 + 默认库保护 | `service.py` |
| 文档上传与解析（txt/md/pdf/xlsx/csv） | 另加 docx | `loaders.py` |
| 文本切分与嵌入 | 标题感知切分 + TF-IDF | `chunking.py` / `index.py` |
| 候选召回 / 关键词重排 / MMR / 二次扩召回 | 全部实现 | `search.py` |
| 批量文档异步索引 Job（进度、取消） | 协作式取消 + 进度轮询 | `jobs.py` |
| 聊天记录持久化（SQLite） | 会话 + 消息 | `store.py` |
| 生成 RAG 评估数据集 | 反推题目 + hit@K/MRR | `eval.py` |

界面：左侧导航「知识库」页 —— 左侧库列表，右侧四个标签
（文档 / 检索测试 / 索引任务 / 评估集）。

## 二、与模板的两处必要差异

**1）向量层用本地 TF-IDF，不用 Qdrant + 嵌入模型**

本工程要离线可用、打包成单机程序；DeepSeek 也没有 embeddings 接口
（实测 `/v1/embeddings` 返回 404）。TF-IDF 同样是向量空间检索，
零外部服务、毫秒级，对术语密集的电力文本够用。

**2）单进程内嵌，不用 Docker + Go 后端 + React 前端**

这里是原生桌面程序，知识库跑在同一进程，界面用原生控件，不引入浏览器引擎。

- 只写**实际读到**的数字（如 ATC 的 `postError>0.2`、`kloop=28`、

- 凡涉及本工程能力边界，如实写"未覆盖"（如碳强度约束尚未实现）。

### 第三批（22–28）：诊断与决策

这一批回答的是「**出了问题怎么办**」，不是「概念是什么」。

| 文件 | 主题 | 解决什么问题 |
|---|---|---|
| 22_储能与灵活性资源 | 储能、需求响应、SVG、SOP | 配多少储能能多接光伏；为什么「0.5h 储能挡不住 4h 大发」 |
| 23_电压调节与无功补偿 | 分接头、电容器、逆变器无功 | 电压越限了还能怎么办；为什么调分接头救不了电压分布 |
| 24_台区与低压网拓扑 | 台区接线、三相四线、Dyn11 | 为什么同一馈线两个台区结论相反 |
| 25_新能源出力特性与场景构建 | 光伏/风电特性、典型日 | 哪些时刻最不利、场景怎么选出来的 |
| 26_经济性与投资评估 | 回收期、LCOE、线损价值 | 接这个划不划算（并说明本工程不做经济性） |
| 27_事故应急与供电可靠性 | N-1、转供、温度降容 | N-1 后还能接多少（并说明本版不做） |
| 28_知识库主题索引 | 按「想问什么」导航 | 27 篇怎么找 |

第三批里几个**反直觉结论**值得单独记：

1. **逆变器无功最多约 33% 装机**（pf=0.95 时 `Q ≈ 0.329P`），
   抵不掉长低压线的电压抬升 —— 所以「让逆变器吸无功」
   替代不了缩短供电半径。
2. **调分接头只能平移电压，不改变分布形状** ——
   末端合格了首端就超限，这是「只看平均电压」最容易踩的坑。
3. **留裕度不等于做了 N-1**。裕度是粗放空间，N-1 要逐元件枚举校验。
4. **夏天能带的负荷比春秋少** —— 载流量按环境温度修正（40℃ 约 0.88 倍）。
5. **可开放容量用完也意味着没有转供能力** —— 转供需要相邻线路有余量。

## 四、检索流水线

```
① 切分      按标题切成小节，带标题路径；超长再按段落聚合（450 字，重叠 80）
② 召回      关键词 BM25  ∪  TF-IDF 向量余弦
③ 重排      正文覆盖率（领域短语 + IDF 加权）× 标题命中 × 答案承载信号
④ 扩召回    top1 分低于阈值时用领域同义词再召回一次
⑤ MMR       抑制重复块占满结果
```

### 调优中修掉的四个真问题（都有实测依据）

**1）BM25 按"当次最高分"归一化 → 改成按查询 IDF 总量归一**

原做法下，只命中一个泛词的段落也能拿满分。实测：问
「GBD 和 ADMM 有什么区别」，某段只出现"区别"二字就排到第一，
而真正同时含 GBD 与 ADMM 的段落只有 0.45。
改成 `原始分 ÷ 查询词 IDF 总量`，含义变成"覆盖了查询里多少信息量"，
是绝对量纲，不再取决于谁碰巧最高。

**2）领域词表最长匹配**

纯 2-gram 固定步长会错切：「物理可开放容量」→ `物理/可开/放容`，
"放容"是伪词，真术语被切碎就检索不到。改用 `DOMAIN_TERMS` 最长匹配。

**3）覆盖率闸门**

一个查询短语都没命中的段落，乘 0.35 压制。

**4）比较类意图词进停用词**

「区别/差异/对比/比较」和「什么/怎么」一样不含领域信息。
留在里面会让只提到"区别"的段落凭空命中。

**5）答案承载信号**

字面命中 ≠ 回答了问题。问判据时优先**真的给出数值区间**的段落（×1.45）；
问定义时优先概念章节（×1.35）；问文献时优先文献索引章节（×1.55）。

**6）索引缓存带分词器版本**

缓存只按文本内容做键时，改了停用词仍会命中旧缓存，新规则"看起来没生效"。
`TEXT_VERSION` 变更即自动失效。

## 五、用法

### 界面

**知识库** 页：

- 左侧 `＋` 新建库；「删除该库」（默认库受保护）
- **上传文件**：多选，支持 md/txt/csv/xlsx/docx/pdf，
  上传后自动建索引；逐文件报告成功/失败原因
- **新建文档**：直接写 Markdown（用 `##` 分节有利于检索）
- **重建索引**：清掉块重新切分（文档改动后或检索异常时用）
- **生成评估**：反推题目并跑分，给出 hit@1/hit@3/MRR 与未命中样例
- **检索测试**：显示得分、覆盖、命中词与第 1 名原文，便于判断排序

### 代码

```python
from hc_agent.knowledge import KnowledgeService

svc = KnowledgeService()                      # 首启自动建库+灌内置+建索引
svc.list_kbs()
svc.create_kb("地区细则", "本地区受理细则")
svc.add_files(kb_id, ["规范.pdf", "细则.docx"])   # 逐文件返回结果
job = svc.index_kb(kb_id)                     # 异步
svc.job_progress(job.job_id)                  # 进度
svc.cancel_job(job.job_id)                    # 取消
svc.search("电压越限的判据", top_k=3)
svc.as_context("为什么容量是 0")               # 拼给大模型的上下文
```

## 六、与问答的接法（数字安全边界）

```
用户问题 ──▶ 检索知识库 ──(方法说明)──▶ 系统提示（补充上下文）
用户问题 ──▶ DeepSeek ──(工具调用)──▶ 本地产物 ──(实测数字)──▶ 回答
```

**知识库只提供"方法/口径"的解释，绝不提供实测数字。**
系统提示明确禁止引用知识库里的示例数字，否则旧数值会污染实时结论。

## 七、已知限制

1. **PDF 需文本层**，扫描件不支持（需 OCR）。依赖 `pypdf`，打包时需确认随包。
2. 检索是**词法级**不是语义级。跨两篇的复合问题 top-1 可能落在通用章节，
   但 top-3 上下文通常都包含，回答不受实质影响。
3. 用户知识暂**不支持子目录分组**（会递归扫描，但不显示分组）。
4. 评估集题目由文档反推生成，**只验证检索能否找到出处**，
   不验证回答正确性 —— hit@1 不等于问答准确率。
