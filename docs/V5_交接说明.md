### 两个已修的 bug（避免重犯）

1. **`bands` 解析成字符串 `"voltage"`**：插入字段时把
   `rule_class=(as_str(...) or _infer_class(...))` 截断，导致 `bands` 接到了 `rule_class` 的值。
   修正方式是恢复括号表达式，让两行各归各位。
2. **`rules.search.upper_kw: 3000` 压住 `task.search.upper_kw`**：
   原逻辑 `if k not in search_cfg and k in task`，规则包存在该键时 task 永不生效。

## 五、当前故障（本轮未解决）

改完优先级后，V5 结果变成：

```
capacity_physical_kw = 0.0
capacity_managed_kw  = 0.0
search_status        = ok
binding_constraint   = VOLTAGE_LIMIT
```

但同一运行的 `results/constraint_results.csv`：

```
231 行，失败 0 条
```

**两组结论互相矛盾**：约束表无越限，却报「0 kW + 电压越限」。

### 三个可疑点

1. **绑定约束取值来源与约束表不一致**
   绑定可能取自最后一个不可行试探点，而该点未写入 `constraint_results.csv`。
   相关代码：`hc_agent/model/constraints.py` 的 `evaluate_voltage()`（约 178 行起）、
   `hc_agent/capacity_search.py` 的 `_bisection_search()`（约 130 行起）。

2. **基线判定把 unknown 当 fail**
   0 kW 判不可行，但表里无记录，怀疑某母线在 bands 下取到 `unknown`（如 `base_kv` 缺失），
   而 `evaluate_constraint()` 对 `None` 返回 `"unknown"`，外层是否把它计为不可行需核查。
   相关代码：`hc_agent/rules.py` 的 `evaluate_constraint()`（约 384 行）。

3. **`search_status=ok` 与 `capacity=0.0` 不自洽**
   外层缺少「没有可行点」与「真的不可行」的区分。
