## 一、DL/T 2041 承载力评估导则

配电网承载力评估**唯一的直接行业标准**，此前知识库完全没提。

| 版本 | 状态 |
|---|---|
| DL/T 2041-2019 | 已被替代 |
| **DL/T 2041-2025** | 国家能源局 2025 年第 7 号公告发布，**2026-06-18 实施** |

两处关键变化：

1. **承载力分两级**
   - **系统级**：行政区/调度区可接入的**最大装机容量**，用时序生产模拟
   - **设备级**：变压器供电范围内的最大装机，在**反向负载率不越限**条件下计算
   - 本工程做的是**设备级**；系统级需要 8760 电量平衡，本工具不做

2. **红黄绿取消 80% 硬指标**，改按可开放容量区间判定

另明确了设备级评估的典型时刻：**春秋季工作日午间、分布式电源出力最大时**。
这恰好印证本工程"高光伏 + 低负荷"场景的设计思路。

新增知识库第 31 篇，并补进《15_参考文献索引》的"承载力评估导则"分类。

**如实标注的缺口**（文档第八节）：没有做逐级约束（下级服从上级）、
没有系统级评估、红黄绿档位与新版不一致、典型时刻未强制校验。

## 二、口径绑定凭证 `B = {F, v_calc, Θ, γ}`

文档术语表的定义，本工程此前只有散落的 `snapshot_id` / `rule_version` /
`engine_fingerprint`，**没有自动失效机制**。

```python
B = { F,        # 数据指纹：输入包 sha256
      v_calc,   # 计算版本：引擎 + 接口 + Python + Agent
      Θ,        # 口径：规则包、拓扑版本、技能版本、快照
      γ }       # 参数：同时率、裕度、规则文件哈希、搜索方法
```

`hc_agent/caliber.py` 实现：

- `from_run()` 从产物**重建**凭证（不是读记录，是现算）
- `check()` 与当前环境逐分量比对
- **失效不抛异常**，返回结构化差异 —— 因为"失效"是要展示给用户的正常状态

实测：复制 FD002 改一行 `rules.yaml`，立刻判定失效，并精确指出
`rules_yaml_sha` 由 `af68f36b…` 变成 `a3a47295…`。

设计要点：**当前环境取不到值的键不参与比对**（取不到 ≠ 变了）。

## 三、质量治理产物标准化

文档 9.5 规定 `quality_issues.csv` 是**运行根目录**的契约文件，十列：
`issue_id/file/sheet/row/field/object_id/severity/code/message/blocking`。

本工程的十列早就一致（`io/schema.py`），问题在**落点**：只写 `results/`，
`FD002` 根目录没有该文件，导致"数据质量过不过关"无法从产物回答。

- 新增 `io/quality.py`：统一落盘（根目录 + `results/` 双写）与读取统计
- **空清单也要写表头** —— "检查通过"和"没检查过"是两件事
- 缺文件时 `exists=false` 且明确说"没查过"，**不判为通过**
- 已给 FD002/FD001/APP001 补建

## 四、验收指标矩阵（开发文档 11.2）

九条指标，四态判定：

| 状态 | 含义 |
|---|---|
| `pass` | 达标 |
| `fail` | 未达标 |
| `unknown` | 无数据（**不等于通过**） |
| `unavailable` | 不适用（需要专家标签/人工基准） |

FD002 实测：达标 4、不适用 3、无数据 1、未达标 1。
其中 **"适配引擎数 1 种 < ≥2 种"被判为未达标** —— 这是如实反映，
不是美化。需要专家标签的"红黄绿一致率"明确标不适用，
不拿本工具的输出冒充专家标签。

## 六、顺带修的三个真问题

1. **算例在子目录里找不到**（用户把三个算例收进了 `桌面/opendss算例/`）
   → 查找改为**递归 3 层**，浅的优先、结果稳定。用户整理桌面是正常习惯，
   不该逼他改回来。

2. **`PermissionLevel(99)` 构造抛 ValueError**
   永久禁用动作的异常构造时自己又崩一次 —— 异常在构造时炸是最糟的失败方式。

3. **`verify_qa` 里 `cap` 为 `None` 时 TypeError**
   某次运行没有容量结论就把整份测试打挂。
