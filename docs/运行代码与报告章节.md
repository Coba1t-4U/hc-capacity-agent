## 一、运行代码（运算过程 → 运行代码）

### 为什么需要区分"实际执行"和"等效复现"

产物里**不一定有**原始命令行。本项目从这一版开始才在 `manifest.json`
里记录 `invocation`；之前产生的运行没有这条记录。

所以界面必须如实分两种情况：

| 标记 | 含义 | 依据 |
|---|---|---|
| **实际执行** | 运行时确实记录下来的触发信息 | `manifest.invocation` 存在 |
| **等效复现（重建）** | 按运行参数拼出来、可照着重跑的命令 | 无 `invocation`，由 `input_root` / `max_slices` 等重建 |

把重建的命令说成"实际执行"是误导 —— 用户会以为当时就是这么敲的，
排查问题时会被带偏。

### 页面上有什么

1. **命令行**（可「复制命令」），带上面那种标签 + 触发渠道（cli / engine-host）
2. **实际执行轨迹** —— 这部分始终是真实的：
   - 执行了哪些阶段（`S01 → S02 → …`，来自 `checkpoints.json`）
   - 有多少个阶段不是 `ok`
   - 调用引擎多少次（来自 `search_trace.csv` 行数）
   - 引擎侧日志位置与行数
3. **阶段明细表** —— 每步的状态与耗时
4. **引擎侧记录** —— `engine/opendss_adapter.log` 的位置，
   排查"为什么这一步失败"要看它

### 新增运行会记录真实命令

`pipeline.py` 在 S01 冻结输入时写入：

```json
"invocation": {
  "argv": ["..."],                 // 进程真实参数
  "channel": "cli|engine-host",    // 触发渠道
  "cwd": "...", "python": "...",
  "equivalent_cli": ["python","-m","hc_agent.cli","run", ...],
  "equiv_cmdline": "python -m hc_agent.cli run --input ... --out ..."
}
```

`equivalent_cli` 是刻意加的：GUI 触发时 `argv` 是窗口程序的参数，
对复现没意义；拼一条等价 CLI 才是用户能直接跑的东西。

## 二、报告章节（结果与证据 → 报告章节）

报告 9 章，每章一个「问这个」按钮，点了带着该章问题跳到问答页。

| 章 | 入口问法 | 答案来源 |
|---|---|---|
| 1 任务概况 | 任务概况是什么？ | `run_summary` + `manifest` + 门禁记录 |
| 2 数据与口径 | 用了哪版规则？数据与口径是什么？ | `rule_package`、快照、`caliber.items/assumptions` |
| 3 计算过程 | 计算过程怎么样？ | 场景数/时间片/收敛/搜索方法/阶段轨迹 |
| 4 评估结果 | 还能接多少？为什么是这个值？ | `capacity` / `summary` |
| 5 接入校核 | 接入校核结论是什么？ | `results/access*.json` |
| 6 风险与缺口 | 有什么风险？ | `unknowns`、`risks`、`caliber.unsupported` |
| 7 独立验证 | 复算通过了吗？ | `verification.json` |
| 8 人工审批 | 发布门禁过了吗？ | `review/release_gate.json` |
| 9 证据索引 | 证据索引在哪？ | `report_manifest.traceability`、`evidence_refs`、审计事件数 |

### 关键原则：只说这一章的产物

- **第 5 章没有产物就明说"本章为空"**，并解释"只有业务场景是
  接入校核/并网申请时才生成该章，纯容量评估不会有它，这不是漏算"。
  **不能拿容量结论去凑第 5 章** —— 那会让用户以为做过接入校核。
- 章节所需字段缺失（如 `caliber` 为空）时如实说明，不推断。
- 问的是**当前选中的那次运行**：按钮会把运行号拼进问句
  （`FD002 计算过程怎么样`），避免答成"最近一次"。

### 一个显示上的坑

`run_summary.constraint_rows` 不是整数，而是
`{count, status_counts, digest, rows:[...]}`。第一版直接把它插进回答里，
把整包（含 123 行明细）打了出来，答案被刷屏。现在只取 `count`
与 `status_counts`。

## 三、验证

`tests/verify_report_chapters.py` —— **67 项**：

- **运行代码**：有命令行、含 `hc_agent.cli run`、带输出目录；
  无 `invocation` 时**必须**标为等效复现且说明"不是当时实际执行"；
  引擎日志能找到且行数 > 0；执行摘要含阶段数与引擎调用次数
- **invocation 采集**：三元组齐备、等效命令含参数、记录 cwd/解释器
- **报告入口**：`find_report_in` 能按任意目录找到报告、找不到返回 None；
  跑完记录 `last_run_id/last_run_dir` 并重画页面；结果区块四个按钮齐备
- **9 章**：报告清单 9 章 = 界面章节表 9 条；9 个意图识别正确；
  常规问题（判据/最低电压/为什么是 0）**不被章节规则抢走**
- **逐章内容**：每章答案里的数字与产物一致；
  第 3 章不打整个约束字典；第 5 章无产物时如实说空且不拿别的章凑
